# ADR 0001：第一版只实现 SteamOS 游戏模式绘制平台

日期：2026-08-05  
状态：已接受

## 背景

项目需要为其他程序提供统一覆盖层，但游戏模式与桌面模式中运行游戏时的渲染路径不同。同时实现两套渲染器会扩大第一版的兼容和调试范围。

项目本身不需要采集游戏 FPS。业务程序应自行获取数据，并通过受限接口提交给绘制平台。

## 决策

第一版：

- 只支持 SteamOS 游戏模式的 Gamescope 外部覆盖层。
- 只建设绘制平台、第三方数据接口、Decky 管理和安全生命周期。
- 不实现 FPS 或交换链探针。
- 桌面游戏渲染器推迟到第二阶段。

## 结果

- 第一版可以围绕 SteamOS 当前 Gamescope/MangoApp 协议建立明确兼容基线。
- 日常渲染开发可在 KDE 的嵌套 Gamescope 中完成。
- 最终集成仍需在真实游戏模式测试，但只需热重启 MangoApp 用户服务，不需要反复重启 SteamOS。
- 共享场景模块应保持与渲染后端解耦，为后续桌面游戏渲染器保留接口。
